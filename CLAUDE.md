# chaos-adept

Вторая сборка Minecraft (после «Осколка Хаоса»): техно-магическое путешествие с прокачкой артефактов. Свои моды:
- **«Ядро»** (`adept_core`, папка `core/`) — вся механика, публикует события и точки управления;
- **«Сюжет»** (`adept_story`, папка `story/`) — история, журнал, тексты, катсцены; слушает события ядра.

Платформа: Minecraft 1.21.1, NeoForge 21.1.264, Java 21. Сборка, запуск и CI описаны в [README.md](README.md). Состав сторонних модов — [docs/mods.md](docs/mods.md).

Работаем на русском: ответы, тексты, коммиты, pull request.

## Правила

- Согласованные решения сразу переносить в нужный документ `docs/`. Документы держать короткими: решения и правила, без пересказа обсуждений. Решение расходится с документом — отметить и уточнить, какое верно.
- Вопрос к другому направлению — в [docs/questions.md](docs/questions.md), в раздел адресата: вопрос, от кого, дата, статус (открыт / решён: где записано).
- В начале работы: подтянуть свежий `main`, проверить свой раздел в `docs/questions.md`.
- Каждая задача — своя ветка и pull request; вливать после зелёного CI.
- API событий ядра (`ru.adept.core.api`) меняет только «Ядро». Новая механика ядра сразу получает события и точки управления для сюжета.
- В игре проверяет только пользователь. Честно писать, что не проверено («в игре не проверено»), полного прохождения на тестах нет — итоговая отладка на стримах.

## Принципы сборки

- Игрок всегда идёт вперёд, телепортов назад нет.
- Артефакты прокачиваются по сегментам: у сегмента два пути по 3 ступени (оба можно закрыть) и вершина. Пары артефактов — исключающий выбор на всё прохождение.
- Развитие «магия → техника»: сначала магия подпирает сырую технику, потом лишь дополняет.
- Руны только на расходниках; ванильные зачарования на артефакты не накладываются.
- Узлы магии редкие, не больше одного на биом; уровень задаётся при генерации и не меняется.
- Опоры (боссы) — вехи по актам, бой в любом порядке; полностью свои, под свой биом.
- Сторонние моды — только генерация, мобы, библиотеки, удобства и оптимизация.

## Как писать код

- Код искать и оценивать изменения через граф Graphify (навык `.claude/skills/graphify`): где определено, кто вызывает, что заденет правка, какие геймтесты её проверяют.
- Числа баланса — в конфигах (`config/adept_core-common.toml`, `BalanceConfig`), не в коде.
- Для точечных проверок — отладочные команды `/adept …` (права 2), у каждой новой части свои.
- До готовых моделей — заглушки сразу с размерами и хитбоксами будущих моделей (размеры — [docs/mobs.md](docs/mobs.md)).
- Свой рендер совместим с Iris: только ванильные рендер-типы и частицы, свечение слоем eyes/glowmask, своих core-шейдеров и пост-эффектов без запасного пути нет ([core/RENDERING.md](core/RENDERING.md)).
- У каждой ступени и вершины артефакта — полноценное описание в игре (что делает, числа, условия срабатывания). Текст прогнать через навык humanizer до pull request. Тексты сюжета — тоже через humanizer.
- Спрайты, текстуры и интерфейсы (окна, шкалы, экран игрока) делать и проверять с навыком ui-ux-pro-max: палитра, читаемость, правила UX для игровых окон.

## Как общаться

- Пользователь живёт в России: учитывать доступность сервисов и площадок.
- Предлагать коротко, без лишних привязок и усложнений; пользователь часто правит предложения.
- После согласования направления конкретику (числа, названия, атаки) придумывать самостоятельно и показывать результат.
- Большие задачи делить на части, держать фокус на текущей.
